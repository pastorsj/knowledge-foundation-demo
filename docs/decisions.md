# Decisions

The choices that shape this repository, and the workarounds they required. The repository started as the
market-analysis demo (itself rebuilt from an AI-Q prototype on 2026-09-29) and was converted to NVIDIA Knowledge
Foundation on 2026-10-02 ([design](superpowers/specs/2026-10-02-knowledge-foundation-design.md)). Decisions 1 to
20 come from the market demo: those that still hold are kept as they are, amended ones say what changed, and
removed ones say what replaced them. Decisions 21 onward were made for the conversion.

## Decision log

| # | Decision | Why | Where |
|---|---|---|---|
| 1 | Hermes Agent is the only agent, running in an OpenShell 0.1.2 sandbox built only from official artifacts (images by digest, CLI by checksum), with the release pinned in one file | A real sandbox boundary without a custom controller: about 400 lines of configuration and script replace roughly 5,500 to 6,000 lines of controller and VM integration | `infra/openshell/`, `agent/`, [OpenShell](openshell.md) |
| 2 | Two endpoints, inference and retriever, each with its own base URL and key (the retriever key defaults to the inference key, so one build.nvidia.com key serves both); never `NVIDIA_API_KEY` or `NVIDIA_BASE_URL`. Parse has a third, optional one (`PARSE_*`) for a hosted endpoint | An OpenAI-compatible inference endpoint may serve the agent's models but not the embedder or the VL reranker. Hermes and LangChain read the `NVIDIA_*` names as global defaults, so they would leak between services | `.env.example`, [configuration](configuration.md) |
| 3 | Switchyard 0.3.0 runs outside the sandbox and is the only holder of the model keys on the agent path. The capable model may have its own endpoint and key (`CAPABLE_BASE_URL`, `CAPABLE_API_KEY`) | The sandbox never sees a model key, the model choice changes without rebuilding the sandbox, and a frontier model can come from any OpenAI-compatible provider | `infra/switchyard/` |
| 4 | The default is Nemotron 3 Ultra alone on build.nvidia.com (`passthrough.nemotron`); with a provider that serves a frontier model, Ultra escalating to GPT-6.1 Sol with a GPT-6.1 Sol judge (`escalation.nemotron-gpt`) | The market demo's 2026-10-01 frontier bake-off (16 runs per arm, two graders): Ultra → GPT-6.1 Sol passed 10 and 14, above GPT-6.1 Sol pinned (7, 9) and Claude Opus 5.5 pinned (9, 13), with 10% of agent turns on Sol. Not re-run on the industry packs yet | [Models and routing](models-and-routing.md) |
| 5 | Embedding and reranking on `langchain-nvidia-ai-endpoints` 1.4.3 (embed and rerank clients only) and plain `pymilvus` 2.6 on CPU Milvus 2.6, on every host. No LlamaIndex, no LangChain agents, no LangGraph | Zero code workarounds and a handful of documented configuration items (below); LlamaIndex needed two code workarounds | `tools/retrieval/`, `ingest/` |
| 6 | A plain FastAPI job service. An asyncio runner on SQLite (WAL): one running and four queued jobs, a 1,200 s deadline, cancellation of queued and running jobs, restart recovery and retention | The prototype's Dask cancel did not stop a running job, and a worker crash re-ran it. The runner keeps the needed semantics, with one uvicorn worker because the queue lives in the process | `api/` |
| 7 | **Amended.** The UI is the upstream AI-Q UI (at `bf4e67d1`) re-applied, plus a contract-first execution feature drawn with HTML and SVG, no graph library. Now named NVIDIA Knowledge Foundation, with the industry selector and AI-Q's documents feature restored for "Your data"; the market explorers and the Benchmark tab are gone | A small, reviewable diff from upstream | `ui/UPSTREAM.md`, `ui/src/features/execution/` |
| 8 | Phoenix is private (loopback only) and receives traces straight from Relay, with no allowlist and no collector. Model spans carry the system instructions and the current turn, tool results included | The allowlist existed to protect a Phoenix that others could reach; OpenShell does not cap OTLP bodies | `agent/profile/relay-plugins.toml`, [operations](operations.md#phoenix) |
| 9 | One lifecycle script, `scripts/demo.sh`, and no Makefile | The bring-up must be ordered around the sandbox, which Compose does not manage | `scripts/` |
| 10 | **Removed.** Two market packs behind a single active data pack (`DATA_PACK`, `/data/active`) | Replaced by the co-resident catalog (21) and industry packs ingested like uploads (27) | – |
| 11 | Services share JSON contracts only: a tool registry, event and receipt types generated from the API's Pydantic models into JSON Schema and TypeScript, and the hand-written catalog manifests | One definition per tool and per event; `--check` catches drift | `contracts/`, `scripts/gen-contracts.sh` |
| 12 | The job's source scope is injected into tool arguments by the plugin's `pre_tool_call` hook; tools filter on `source_ids` | Replaces signed scope grants with an argument the tools already take | `agent/profile/plugins/`, `api/src/demo_api/routes/internal.py` |
| 13 | The plugin reports each model call to `POST /internal/hermes/jobs/{id}/llm-calls` | The only path for per-call token counts to reach the UI and exports | `infra/openshell/providers/receipts.yaml` |
| 14 | Receipts fail closed: a registered tool call with no receipt fails the job | An answer must never cite evidence that was not recorded | `api/src/demo_api/jobs/executor.py` |
| 15 | **Removed.** Kumo prediction as a tool on the market-analytics server | Replaced by the `prediction` MCP server (28) | – |
| 16 | **Amended.** Auto Ontology was required and seeded from each pack's ontology. It is now optional (`ontology` profile), still a submodule (`update = none`) plus three patches in trusted service mode on loopback only, and needs repository access while `NVIDIA/auto-ontology` is private | The DuckDB tables tool (24) answers the structured questions; see 29 | `tools/auto-ontology/` |
| 17 | The replay bundle (v2) is committed with its pack, now one per industry, and the UI replays it without the API | The demo can be shown with no keys, no GPU and no network access to the endpoints | `data/packs/<id>/recordings/` |
| 18 | One `uv` project and `uv.lock` per service, Python 3.12, one `ruff.toml`; no root workspace | Services resolve their dependencies independently (docling, DuckDB, Kumo and Auto Ontology pins do not collide) | every service directory |
| 19 | Trimmed rigor: unit and contract tests per project, a skills lint, Switchyard template dry-runs, Compose config checks, a Playwright smoke suite, all run locally with `demo.sh test` and pre-commit (no hosted CI) | Enough to keep a demo correct, without a release process | `scripts/demo.sh`, `.pre-commit-config.yaml` |
| 20 | **Removed:** the Benchmark tab's CPU/GPU comparisons of market tools and Milvus indexes went with the market tools. **Kept:** voice input, the original demo UI's microphone, transcribed by NVIDIA Nemotron ASR on build.nvidia.com with an optional deletion-only cleanup | Nothing in the knowledge stack has a CPU/GPU pair to compare | `api/src/demo_api/speech/` |
| 21 | Every industry pack and the user's workspace are co-resident in one knowledge catalog (`/knowledge`); sources are namespaced (`retail.policies`, `workspace.documents`); readers read the manifests on every request | Switching industry rebuilds and restarts nothing, and the sandbox is never recreated for data, because every tool schema is data-independent | `contracts/catalog/`, [architecture](architecture.md#the-knowledge-catalog) |
| 22 | The ingest service is the only writer of the catalog: the volume is read-write there and read-only everywhere else; writes are validated and atomic | One writer means no locking between services, and a reader sees a whole manifest or the previous one | `ingest/`, `compose.yaml` |
| 23 | Documents go through docling; PDFs and images through docling's official `nemotron_parse_v2` preset on its API engine, against NVIDIA Nemotron Parse 2.0 served by vLLM 0.27.1 as the model card prescribes (pinned revision, the card's tied-head patch). Born-digital formats use docling's own backends. Without Parse, PDFs fall back to their text layer | The documented path for Parse 2.0 in docling, with no custom parser; the Parse NIM has no GB10 profile while vLLM is multi-arch. A spike on the Spark parsed a two-page PDF in 2.3 s and a scanned page in 1.8 s | `ingest/src/demo_ingest/documents.py`, `infra/parse/entrypoint.sh`, [ingestion](ingestion.md) |
| 24 | Structured questions go to a DuckDB tool, `query_tables`: one SELECT checked with sqlglot, run in a separate worker on an in-memory DuckDB with the sources attached read-only, external access off and the configuration locked, 10 s and 200 rows | Two independent locks: a query the guard misreads still cannot read a file, change a setting or write. The data viewer's rules, reused | `tools/tables/` |
| 25 | The execution graph has one component per MCP server (`COMPONENT_BY_SERVER`), not per tool family | `query_tables` and `ask_question` share the `structured_retrieval` family but are different systems (DuckDB, Auto Ontology) | `api/src/demo_api/events/execution.py`, [contracts](../contracts/README.md) |
| 26 | Host ports form a block of their own: 3300, 4300, 6306, 8300, 8320 to 8322, 8330, 8340, 3303, 18380 and 18381, all on 127.0.0.1 | The demo shares a DGX Spark with other demos (port 6006 is held by another one); `doctor` refuses a taken port | `compose.yaml`, `scripts/lib/doctor.sh` |
| 27 | An industry pack is raw files plus metadata (pack format v3), ingested through the same pipeline as an upload; its files come from a seeded generator committed with it. Four industries: Retail, Manufacturing, Healthcare, Financial Services | The packs exercise exactly what a user's upload does, scanned pages included, and adding an industry needs no service change | `data/packs/`, `data/schemas/`, [data packs](data-packs.md) |
| 28 | Predictions are their own MCP server, `prediction` (`kumo-relational-client` 1.0.2, graph from the source's DuckDB with the catalog's keys). The Kumo NIM is amd64 only, so on a DGX Spark the `prediction` profile points at a remote NIM (`KUMO_RELATIONAL_URL`, through an SSH tunnel); without one, `predict` answers `available: false` | The client and its engine have aarch64 wheels, so the server runs anywhere; the tool states why a prediction is unavailable instead of failing | `tools/prediction/`, [operations](operations.md#kumo-through-a-remote-nim) |
| 29 | Auto Ontology's seed is removed: it serves one structured source (`AUTO_ONTOLOGY_SOURCE`, default `retail.sales`) and builds its ontology with upstream's own ingestion | The market packs' hand-written ontology models are gone, and the catalog's profiled keys and descriptions already describe every table | `tools/auto-ontology/`, `compose.yaml` |
| 30 | Uploads use AI-Q's documents contract (`/v1/collections/...`, `/v1/documents/{job_id}/status`), with optional stage fields; the API forwards it to ingest | AI-Q's upload UI can be restored nearly verbatim, and upstream's schemas ignore the extra fields | `ingest/src/demo_ingest/app.py`, `api/src/demo_api/routes/documents.py` |

## Documented workarounds

Each entry is a deliberate deviation from what the upstream project would suggest, with the condition that removes
it.

| Workaround | Why | Where | Remove when |
|---|---|---|---|
| Hermes patch 0001: forward run metadata into the Relay turn | Joins Phoenix traces to jobs | `agent/patches/` | A released Runs API forwards request metadata |
| Hermes patch 0002: exact per-run toolsets | Each job gets only its sources' tools and cannot widen them | `agent/patches/` | A released Runs API accepts a non-widening per-run toolset list |
| Hermes patch 0003: `tool_call_id` on tool events | Joins graph nodes to receipts | `agent/patches/` | A released Runs API emits it on both events |
| Hermes patch 0004: read `read_only_hint` from mcp 2.x annotations | Otherwise every data tool counts as write-capable, and a call cut off by a server restart fails instead of being replayed | `agent/patches/` | Hermes reads the mcp 2.x name |
| Seed `HERMES_HOME` at build time | OpenShell ignores the image's entrypoint, so Hermes' init never runs | `agent/Dockerfile` | – (a property of OpenShell) |
| The plugin records a receipt in whichever of `transform_tool_result` and `post_tool_call` fires first | Hermes' agent loop runs `transform_tool_result` first, so a receipt posted in `post_tool_call` came too late to cite | `agent/profile/plugins/execution_receipts/` | Hermes fires the hooks in one order |
| `HERMES_STREAM_READ_TIMEOUT=900`, `HERMES_STREAM_STALE_TIMEOUT=600` | An escalation template buffers judged replies, so a reply can stay silent for minutes | `agent/Dockerfile` | – |
| NeMo Relay pinned below 0.9 (the build fails otherwise) | 0.9 needs a collector to export to Phoenix from the sandbox | `agent/Dockerfile` | Relay exports plain OTLP/HTTP from the sandbox again |
| `API_SERVER_KEY` is a real value in the sandbox, not a provider placeholder | Hermes checks it on inbound requests; placeholders resolve only on outbound ones | `scripts/lib/openshell.sh` | OpenShell resolves placeholders for inbound checks |
| Record and remove the sandbox's anonymous volumes | OpenShell 0.1.2 deletes sandbox containers without them | `scripts/lib/openshell.sh` | OpenShell removes them |
| Phoenix runs through `infra/phoenix/serve.py`, which defaults uvicorn's keep-alive to 120 s | OpenShell 0.1.2's proxy fails the first request on a connection the server closed as idle, and Relay does not retry | `infra/phoenix/serve.py` | The proxy closes the sandbox side too, or Relay retries |
| The trace lookup falls back from `aiq.job.ref` to `session.id` | While a turn runs, Relay has not exported the span carrying `aiq.job.ref`; Switchyard's spans carry the job id | `api/src/demo_api/phoenix.py` | – |
| Switchyard and the tool servers' spans name the agent's Phoenix project | Phoenix files a trace under the project of its first span, which is often Switchyard's | `compose.yaml` | – |
| Switchyard runs standalone, built from crates.io | NeMo Relay's Switchyard plugin does not pass the session id the escalation latch needs, and there is no official image | `infra/switchyard/Dockerfile` | Relay passes the session id; an official image exists |
| Switchyard's root filesystem is not read-only (uid 1000, no capabilities instead) | Compose writes environment-sourced secrets into the container, which a read-only root refuses | `compose.yaml` | Compose mounts such secrets without writing |
| The forwarder's health check probes `/health` | `/v1/capabilities` without the key made Hermes log a rejected key every 5 s | `compose.yaml` | – |
| Builds turn off provenance attestations, Dockerfiles have no `EXPOSE`, and an image shared by several services is built by one of them | Otherwise every build gives an unchanged image a new ID, and `up` recreates containers and the sandbox | `scripts/lib/common.sh`, Dockerfiles, `compose.yaml` | BuildKit and Compose give identical builds identical IDs |
| `demo.sh` passes `.env` with `--env-file` and derives `PARSE_BASE_URL`, `KUMO_RELATIONAL_URL`, `AUTO_ONTOLOGY_URL` and `AGENT_FEATURES` | Passing any `--env-file` turns off Compose's `.env` lookup, and Compose interpolation has no conditionals | `scripts/lib/env.sh` | – |
| Hermes `fallback_providers` names Switchyard's `knowledge-fallback` route (the auxiliary model) | build.nvidia.com can send "Service temporarily overloaded" as the first event of an HTTP 200 stream, and Switchyard 0.3.0 passes it through without a retry | `agent/profile/config.yaml`, `infra/switchyard/routes/` | Switchyard retries and re-routes in-band errors |
| Retrieval and embedding configuration items: `register_model` for the embed model; an explicit `base_url` and key on every client; one rerank request (`top_n = max_batch_size = 200`); the clients' fixed 60 s timeout; retries around every call; manual `embed`/`search`/`rerank` spans; the `==1.4.3` pin with usage telemetry off; the reserved metadata key `image` | Gaps in `langchain-nvidia-ai-endpoints` 1.4.3 | `tools/retrieval/src/demo_retrieval/nvidia.py`, `ingest/src/demo_ingest/embed.py`, `ingest/src/demo_ingest/index.py` | The package lists the model, honours `timeout`, and retries |
| The Parse server loads the model card's `vllm_tied_patch/sitecustomize.py` from the pinned revision | Without it vLLM 0.27.1 leaves the output head untied and the model emits `<s>` until `max_tokens` | `infra/parse/entrypoint.sh` | vLLM ties the head itself |
| Parse requests ask for `max_tokens: 8192`, not the card's 9,000 | The served context is 9,000 tokens, prompt and image included | `ingest/src/demo_ingest/documents.py` | – |
| A PDF falls back to its text layer when Parse is slow or down, and a pack synced that way records no digest | The upload must still finish within its stage, and the next sync must try Parse again | `ingest/src/demo_ingest/documents.py`, `ingest/src/demo_ingest/packs.py` | – |
| A workbook sheet that `read_xlsx` would mistype (from its first data row) or truncate (an empty header cell) is read with openpyxl and typed by `read_csv` | `read_xlsx` types each column from one row and drops unnamed columns | `ingest/src/demo_ingest/tables.py` | DuckDB's excel extension samples more rows |
| DuckDB's `excel` extension and the embed model's tokenizer are baked into the ingest image | No network at runtime; chunks are sized in the embed model's own tokens | `ingest/Dockerfile` | – |
| Every DuckDB writer and reader is pinned to the same version (1.5.5) | An older DuckDB cannot always open a newer file | `ingest/`, `api/`, `tools/tables/`, `tools/prediction/` `pyproject.toml` | – |
| Auto Ontology patches: hide configured schemas from search, report resolution lineage, trusted service mode for MCP | Upstream cannot exclude schemas, reports no typed lineage, and its MCP server accepts only per-caller OAuth | `tools/auto-ontology/patches/` | Upstream ships each behavior |
| Every Auto Ontology model setting is explicit | Unset, upstream falls back to built-in defaults chosen by key prefix, and to `NVIDIA_API_KEY` | `compose.yaml` | – |

Removed with the market demo: the sandbox recreation on a data pack switch (data no longer shapes a tool schema),
the market-analytics restart on a data rebuild, the Data Designer seed and pyarrow workarounds, and the RAPIDS
version pins.
